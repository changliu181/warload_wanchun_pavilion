# warload_wanchun_pavilion

三国战棋 —— 10x10 格子地图上的回合制对战小游戏，用 Pygame 写的小程序。
玩家一执红（蜀，南半场），玩家二执蓝（魏，北半场），双方轮流行动，把对方武将全灭即获胜。
既可以**两人同机对战**，也可以**一人游玩对抗电脑**（见"六、电脑对手"）。

## 文件构成

| 文件 | 作用 |
| --- | --- |
| `warlords.py` | 游戏本体：武将、对局规则、交战结算、绘制、主循环 |
| `constants.py` | 全局常量与配色（屏幕尺寸、地形、规则数值、`AI_*` 旋钮）——改平衡看这里 |
| `config.py` | `map.txt` / `generals.txt` 的解析与校验 |
| `ai.py` | 电脑对手：棋盘走位 + 交战屏决策（不依赖 pygame，可单独测试） |
| `smoke_test.py` | 无头回归测试：两个电脑对打整局，跑规则和电脑判断的改动 |
| `map.txt` | 固定地图配置（地形 + 地名写在一起，不标出生点） |
| `generals.txt` | 武将配置（双方各 20 名，武力 / 智力都是固定值） |

## 运行方式

安装 Pygame 后直接运行：

```
pip install pygame
python warlords.py
```

启动后先进**模式选择屏**：选一人游玩（对抗电脑）还是两人同机；选了一人，再选执蜀还是执魏。
配置在**开局时**读取并校验，有问题不会进主界面，而是弹出一个小窗把出错原因和配置文件路径写出来
（两份配置：`map.txt` 地图（含地名）、`generals.txt` 武将）；
游戏中按 R 会回到模式选择屏重新选，选完才发现配置被改坏的话，会保留当前对局并在战报里提示。

## 一、地图（map.txt）

地图不做随机生成，固定写在 `map.txt` 里。**地形和地名写在同一个文件里**：一格一项，
可通行格写成 `地形:地名`，障碍格只写 `#`。

地形图例（冒号前面的那一个字符）：

- `.` 通路：可通行
- `#` 障碍：不可通行，也不能穿过去
- `C` 城池：可通行，驻守回血更多（+3，通路只有 +2），守城时交战有体力加成（见"交战"）

举几个格子的写法：`.:樊城`（名叫樊城的通路）、`C:襄阳`（名叫襄阳的城池）、`#`（障碍格，没有地名）。

地图配置的硬性要求（`parse_map` / `validate_map` 会逐条校验）：

1. 去掉以 `//` 开头的注释行和空行后，必须**正好 10 行**、每行**正好 10 项**。每格算一项，项与项之间必须有空白——地名长短不一，所以不能再写成 `. . .` 和 `...` 那样紧凑的字符形式。
2. 可通行格一律要写成 `地形:地名`，**一格都不能漏**；障碍格只写 `#`，不能给它起名。
3. 地名不能重复：整张地图里每个地名只用一次。
4. 城池必须**正好 10 座**（数量由 `constants.py` 的 `CITY_COUNT` 决定），城池那一格写成 `C:城名`。
5. 所有通路 / 城池必须**连成一片**，不能有走不到的孤岛格。
6. 出生点不写在地图里：开局时玩家二（魏）的武将随机落在北半场（前 5 行）、玩家一（蜀）的随机落在南半场（后 5 行）的通路或城池上，所以**南北半场各自至少要有自己那份上阵人数的可通行地形**（上阵人数看 `DEPLOY_COUNT`，南北半场由 `SPAWN_ROWS` 决定）。

### 当前这张地图的设计

地图按三国地理布置（上北下南）：北半场是魏（关中 / 河北 / 中原 / 淮南），南半场是蜀与吴（巴蜀 / 荆州 / 江东）。

- 中间是秦岭—淮河一线，横贯东西的障碍带只留 **3 条通路**，每条都只有 1 格宽的线状孔道（没有 2x2 全通路的开阔区）：汉中（第 2 列，关中通巴蜀）、襄阳（第 6 列，中原通荆州）、合肥（第 9 列，淮南通江东）。
- 城池南北各 5 座，合计 10 座。北面：邺 (0,4) 河北、长安 (1,1) 关中、洛阳 (2,4) 中原、襄阳 (4,5) 荆北门户、合肥 (4,8) 淮南；南面：汉中 (5,1) 秦岭孔道、江陵 (7,4) 荆州、建业 (7,8) 江东、成都 (8,0) 巴蜀、长沙 (9,5) 荆南。
- 北半场有一条横贯东西的官道（第 3 行，洛阳—邺—合肥一线），南半场有一条横贯东西的长江（第 8 行，江陵—建业一线），三条孔道都在水陆要冲上收口。
- 三座关城（襄阳 / 合肥 / 汉中）就压在孔道上，**攻方必须啃下城池才能南北通行**。

改完地图保存，游戏里按 R 回到选择屏、重开一局即可按新地图生效（也会重新随机分配出生点）。

### 地名

地名就写在每格冒号后面（城池那格写的就是城名），和地形一起在 `map.txt` 里，
所以不存在"两份配置对不上"这回事。

地名按"上北下南"的三国地理起：北半场是魏（关中 / 河北 / 中原 / 淮南），南半场是蜀与吴
（巴蜀 / 荆州 / 江东 / 荆南），三条孔道上的格子按史书上那条道命名：

- 关中—汉中孔道（第 2 列）：陈仓 → 斜谷 → 箕谷 → **汉中** → 定军山 → 夷陵
- 中原—荆州孔道（第 6 列）：宛城 → **襄阳** → 樊城 → 荆门
- 淮南—江东孔道（第 9 列）：逍遥津 → **合肥** → 巢湖 → 濡须口
- 北面第 3 行是官道（萧关 / 潼关 / 虎牢关 / 寿春一线），南面第 8 行是长江
  （白帝城—夷陵—江陵—赤壁—柴桑—建业一线）

地名显示在哪些地方：

- **地图上**：每格底部写着地名——通路是青灰色，城池是金色。武将站在某一格时，字会被武将牌压住。
- **鼠标悬停**：停在任意格子上都会弹出该格的「地名（地形）」，「被武将压住的地名」这样就能看。
- **侧边栏**：选中武将时，"位于 ……" 显示的就是他所在格的地名。
- **战报**：移动、进攻、进占都会写成地名，比如"关羽 移动 2 格至 樊城（通路）"。
- **交战界面**：标题下写明交战发生在哪一格（如"驻守的 襄阳（城池）"），左右两张卡片上也标着
  攻方从哪一格打过来、守方驻守在哪一格。

改完保存，游戏里按 R 回到选择屏、重开一局即可生效。

## 二、武将（generals.txt）

格式是每行 4 项：`<阵营> <姓名> <武力> <智力>`，例如 `蜀 关羽 21 14`。

- 阵营：`蜀` = 玩家一（红），`魏` = 玩家二（蓝）。
- 武力 / 智力：1-22 的整数。**武力决定战斗判定权重和伤害，智力目前只作展示，不参与任何计算。**

校验要求：去掉注释行和空行后每方**正好 20 名**；同一方内姓名不能重复（两方之间可以重名）；
武力 / 智力必须落在 1-`MAX_STAT`（22）之间。

开局时每方从本方 20 名里**随机抽几名上阵**（人数看 `DEPLOY_COUNT`，两边可以不一样多），抽中的武将再随机落到本方半场的通路或城池上（障碍格不能站人）。
抽将和选出生点都用同一个随机数发生器，所以按 R 重开会重新抽将、重新站位——**同一张地图每局站位都不一样**。

改完保存，游戏里按 R 回到选择屏、重开一局即可按新配置重新抽将。

## 三、核心定义与规则

### 地形

地形用整数枚举定义：`OBSTACLE = 0`（障碍）、`PLAIN = 1`（通路）、`CITY = 2`（城池）。
增加第 4 种地形（比如"树林"），只需在 `TERRAIN_*` 常量后面追加，并把 `TERRAIN_NAME` / `REGEN` 里各补一条即可，其余逻辑会自动跟上。

### 武将属性

- **武力 might**：固定值，1-`MAX_STAT`，决定**交战每回合掉多少体力**（掉血只看对方的武力），是目前唯一参与计算的属性。
- **智力 intellect**：固定值，同样是 1-`MAX_STAT`，目前只作展示。
- **体力 stamina**：可变值，上限 100（`MAX_STAMINA`）。**只有交战会消耗体力**，体力归零即阵亡。
- **移动力 move_points**：每回合重置为 3（`MOVE_POINTS`）。挪到相邻一格花 1 点，发动进攻也花 1 点，所以一回合最多走 3 格。

### 移动

一回合最多走 3 格，走多格可以一次点到位（底层用 BFS 算出每格要花的最少移动力）。
**移动力与体力完全脱钩**：移动不消耗体力，体力见底也能照走 3 格；反过来，移动力耗尽的武将（界面上会盖上灰罩）本回合既不能走也不能交战。

**一格最多站两名武将**（`CELL_CAPACITY`），而且**只有同一阵营能同格**——敌我永远不会站在一格上。
由此分成两件事：

- **能不能停在那一格**：己方在那里不足两名就行；敌方格永远不能停（走进去等于交战）。
- **能不能从那一格穿过去**：只要是通路 / 城池、且没有敌方，哪怕那格己方已经站满两名也能路过。
  所以自家两个人堵住的通道不会把第三个人卡死——**只看终态有没有超员**，不看中途踩过谁。

障碍格既不能停也不能穿。同一格站了两名己方武将时，棋盘上**左右分栏**各画一半
（三字姓名会自动缩小字号塞进半格；半格放不下属性行，悬停提示和侧边栏里还有）。

**选中了武将之后，点高亮格就是走过去**——哪怕那一格上已经站着一名己方武将（还有位置就能停）。
这正是"一格能站两人"的用法：先把甲挪到乙所在的格上，两人并肩。
想改选站在落脚点上的那位时，先点自己的武将取消选中，再点那一格。
同一格有两名己方武将时，连点那一格会在两人之间轮换，轮完最后一个再点一下就是取消选中。

### 回合制

双方轮流行动，只要移动力还没花完，这名武将就能**继续行动**（继续走、或者继续撞下一个人）；
移动力花完了本回合才动不了。空格或回车结束回合，换对方行动。总回合数上限 100（`TURN_LIMIT`，双方各行动一次算 2 回合）。

每回合**结束时**（不是开始时），刚刚行动完那一方的存活武将按**所在地形**恢复体力：
通路 +2、城池 +3、障碍 0（地形上本来也站不了人）。

放在回合末尾意味着：对方回合里挨的打，要**撑过自己整个回合**才回血，不像以前一开回合就白回一口。
如果这名武将上回合**撤退过**，新回合开始时先扣掉透支的行动力（见下面"撤退"）——移动力在回合开头重置，回血在回合末尾结算。

### 交战

把己方武将的移动目标点成"**相邻的**敌方武将格子"（踏进去）即触发交战，消耗 1 点移动力。
必须从相邻格踏入，不能隔着格子冲锋。进攻方在交战期间**不动窝**：打输了就是白花 1 点移动力。

触发后游戏会切到**单独的一屏**（交战界面）打单挑，胜负判定和伤害结算都在这一屏上完成。

#### 守军有两名时：谁先迎战

一格站两名守将时，攻方踏进来后**由守方点将**，决定谁先出阵，另一位排在后面。
攻方把第一名守将打完（**撤退或阵亡都算**）之后，只要这一格还有守将，就自动接着打第二名。

**第二场开打前，双方都可以先选择撤退**（仍是攻方先选）——这时攻方已经打了一场、
守方却是生力军，给两边一个收手的机会。第一场没有这一步，仍然要打满 1 回合才能撤。
界面上会标出"第 N 场 / 共 N 场"，战斗过程里两场的回合也分开记。

#### 交战界面的规则

- **每回合双方同时掉体力**，掉多少只看**对方**武力：取闭区间 `[1, 2 * 对方武力]` 里的一个随机整数
  （上限系数是常量 `LOSS_MAX_PER_MIGHT`）。武力高的武将打得疼，同时也更扛打——因为对方的武力决定了他要掉多少。
  体力 100、武力 20 的武将对砍，平均每回合掉 20 出头，所以单挑通常三五回合见分晓。
- **每回合结束时双方都可以选择撤退**，由**攻方先选**（攻方先选完才轮到守方）。选择撤退的一方算**败方**。
  两边都选继续才进下一回合，所以**交战至少打满 1 回合**，撤退最快也要等第 1 回合打完才能选。
- **体力掉到 0 或以下即阵亡**，同样算败方；双方同一回合都掉到 0 就是**同归于尽**（这局单挑算平局）。
- **打完时双方剩多少体力，就是这场交战的伤害结算结果**——没有额外的伤害公式，
  也没有"胜者也要掉血"这类补充规则，扣掉的就是掉掉的。

#### 撤退

撤退不只是在原地让位，而是要**真的挪走**，两边的规则不一样：

- **攻方撤退**：永远只是回到出发格（攻方在交战期间本来就没动窝），不额外扣移动力。
- **守方撤退**：要自己挑一个**落脚点**撤过去，界面上把每个能去的格子列成一个按钮
  （写着地名和这次要透支几点），步数就是 BFS 算出来的最短距离。
  **退几格就透支下回合几点行动力**，而**同一回合累计撤退格数封顶 `MOVE_POINTS`**：
  退满 3 格，下回合这名武将就走不动了。
  已经撤过的格数会占掉额度——同一个回合里被连着打退，第二次能退的距离就变短；
  **额度不够的撤退不算合法**，那些落脚点根本不会出现在按钮里；额度耗尽后连"撤退"按钮都不给。

撤退走的是 **BFS 路径，可以拐弯，不要求走直线**——先往东一格再往南一格是允许的。
约束是：

- **第一步不能迎着攻方来的方向**——那是朝刀口上撞（攻方站的那一格本来就过不去）。
- 中途每一格要**过得去**：通路 / 城池、没有敌方。和移动一样，己方站满两人的格子可以**穿过**。
- 落脚的那一格还要**停得下**：己方没占满 `CELL_CAPACITY`。所以两个守将可以先后撤到同一格。
- **一个落脚点都没有时，守方就没有撤退的权利**：交战界面上干脆不给"撤退"按钮，只能继续缠斗。
  没有落脚点有两种情形——周围无处可退，或者**本回合撤退额度已经用满**。
  （所以"想撤却无处可撤"这种情况不会再出现，攻方也就能稳稳进占。）
- 只有一个落脚点时不用再点一次，直接撤。

#### 战果落回地图

- **守军被打光**（都撤退或阵亡）且攻方自己没退没死：攻方进占这一格。
- **守方守住**（攻方撤退，或攻方阵亡）：攻方原地不动。
- **同归于尽**：两边都从棋盘上消失，格子空着。

交战不结束进攻方的行动：只要还有移动力，他就能接着走、接着撞下一个人。
被撤退"透支"的只有守方的下回合行动力，不影响攻方。

> **关于城池**：城池加成是**临时**的——开打前守军体力 ×1.2（四舍五入），打完 ÷1.2 还原。
> 两次取整在 0-120 内可以精确还原，所以没受伤的守军血量分毫不差，只是**打的过程中**多扛 20%
> （体力 100 的守将顶到 120，实际多扛 20 点）。这条只对**防守方**生效，而且守的那一格是城池才算。
> 城池同时还是回血更快的据点、以及地盘分里最值钱的一格（城池 3000 分，通路只有 200 分，
> 见"胜负"）。

守城加成让"啃城"明显变贵：同样是 100 体力的守将，守城时你要多打掉 20 点才算赢。

### 粮草

粮草是这一版加的资源，作用是**用机动换体力**。

**产出**：**每 5 个回合入库一次**，落在 **4 / 9 / 14 / 19 …**（回合数 `% 5 == 4`）这些回合的
**开头**，其余回合不产粮。到点的时候每座城池产 1 石，堆在城池那一格上，
所以一批就是全场 10 石（10 座城池各 1 石）。一局 100 回合下来共 20 批、200 石，
开局先攒三回合兵，第 4 回合才见第一批粮。侧边栏回合数旁边写着「下批粮草 第 N 回合」，
不用自己数。产出不看城池归谁占着——粮草**没有归属**。

**堆在格子上**：格子右上角会挂一个 `粮N` 徽标。格子对粮草**没有容量上限**，
没人取就一直涨（全局也是）。

**搬运**：**武将只是脚夫，不是粮仓**——身上不存粮。点目的地时，如果**出发点堆着粮草**、
走的又是人类玩家，会先弹出「携带粮草」问一句搬多少：可选 `－10 / －1 / ＋1 / ＋10` 微调，
或「不带」「全带」两个快捷，确定后才落子（ESC 或「取消」就当没走过这一步）。

**搬多少没有上限**，想一次搬空一座城也行；但**走到目的地就当场卸下**，
并入那一格的粮堆。所以一次「搬运」的净效果就是：**把粮草从出发格挪到落点格**。
带多少都**不影响移动力**，也不影响别的任何数值。

这个设定有两个后果：

- **要往远处送，就得一格格接力**。这一回合搬到半路，下一回合站上去再取一次接着搬。
  中间随便哪个己方武将路过，也能顺手接过去——粮草没有归属，谁站上去都能取。
- **武将身上永远没有粮草**，所以"带着军粮打仗、打输了被缴获"这种事不会发生。
  粮草始终躺在格子上，谁最后站在那一格，谁就攥着它。

**吃粮**：武将和粮草在同一格就能吃，一口吃 1-3 石，**吃几石就花几点行动力**，
1 石回 10 点体力。选中武将后详情框底部会出现 `吃1石 / 吃2石 / 吃3石` 按钮；
能吃到几石取决于三个上限：一口最多 3 石、**脚下**得有那么多粮、还得有同样多的剩余移动力。

所以运粮是有意义的：把城里的粮搬到前线，武将站上去就能在野外回血。

**交战不涉及粮草**：粮草从不带在武将身上，所以攻城、撤退、阵亡都不会让粮草易主——
争夺格上那堆粮原地不动，只是守将走了、攻方站上来了，下一次取粮的人变成了攻方。

### 胜负

- 一方武将全灭即败；双方同时全灭算平局。（单挑里的"同归于尽"只让那两名武将一起下场，
  只有棋盘上某一方真的一个不剩，整局才结束。）
- 回合数达到上限时按**总分**比较，总分 = **将领分 + 地盘分**：

  | 分项 | 算法 |
  | --- | --- |
  | 将领分 | 本方每名**存活**武将各算 `(100 + 体力) × 武力`，逐名求和 |
  | 地盘分 | 每块可通行地域归**行动距离最近**的那一方：城池 `3000`、通路 `200`，外加格上粮草每石 `150` |

  **行动距离**是 BFS 步数：从这一方所有武将同时往外走（多源 BFS），每格取最近的那名武将，
  只在通路 / 城池上量（障碍得绕路），**格上站着谁不影响**——量的是"这一方的兵要几步才能到这儿"，
  不是"现在谁能站上去"。所以地盘是**动态**的：往前压一步，身后一大片就跟着易主。
  两边一样近的格子算**争夺中**，谁也不算——比分板上会单独报一句「争夺中 N 格」，
  免得两边地盘加起来对不上整张图。

  粮草是"格上的物品"，算在**控制那一格**的一方头上：城池产的粮堆在城里，谁控制了这座城，
  连同堆里的粮一起算分（所以把前线的粮搬回家、或者反过来把粮堆留给对方，都会直接影响比分）。

- **比分板常驻在侧边栏**（"选中武将"详情框右边），一局自始至终显示双方的总分 / 将领分 / 地盘分，
  随时能看出谁领先。回合用尽时战报里也会再报一次明细。

把系数调小，单挑会变长、更看运气；调大则更快见分晓。`Battle` 类里另有几个**只影响表现、不影响规则**的常量：
`IMPACT_FRAMES`（掉血动画帧数）、`HIST_ROWS`（战斗过程一屏显示几回合）。

## 五、操作

### 地图上

- **鼠标左键**：点高亮格移动（**点了就是走过去**，那一格上站着己方武将也能走）/
  点自己的武将换选（同格有两人就轮着选，轮完再点一下取消选中）/
  点相邻的敌人格子发动进攻 / 点侧边栏按钮
- **空格 或 回车**：结束回合
- **滚轮**：鼠标放在武将总览上时，上下翻看没显示出来的武将（人少时不用翻）
- **R**：回到模式选择屏重开一局（重新读取 `map.txt` / `generals.txt`，重新抽将）
- **ESC**：退出

选中己方武将时，侧边栏详情框里会多出一排 `吃1石 / 吃2石 / 吃3石` 按钮——
前提是这名武将**脚下有粮**而且还有移动力，点一下就吃。

**点高亮格移动时，如果出发点堆着粮草，会先弹出「携带粮草」**（见"粮草"一节）：
`←/→` 减/加 1 石、`↓/↑` 减/加 10 石，回车或空格是确定，ESC 是取消。
搬多少就卸多少在落点，想空手走就点「不带」再确定。

**轮到电脑时键盘鼠标都不接**（侧边栏会写"电脑思考中…"），只有 R 和 ESC 照样管用。
交战屏上也是一样：谁的回合谁做决定——电脑进攻你驻守的那一格时，
"谁先出阵""继续还是撤退""往哪撤"还是由你点。

### 交战界面上

交战是单独的一屏，进入后**键盘鼠标都归它管**（战斗期间 ESC / R 故意不生效，免得打到一半误触把这一局丢了；关窗口仍然可以退出）。

- **鼠标左键**：点按钮。按钮随阶段变化：
  - `交手` —— 双方同时扣体力，放掉血动画，然后进入选择阶段
  - `继续缠斗` / `撤退（判负）` —— 该方选择是否继续打（先攻方、后守方）。
    守方**无处可退、或本回合撤退额度已用满**时只给"继续缠斗"，"撤退"按钮不出现
  - `X 先出阵` —— 一格有两名守将时，**由守方点将**决定谁先迎战
  - `撤至 陈留（2 点）` 之类 —— 守方点了撤退、且不止一个落脚点可去时，
    把每个能撤到的格子列成一个按钮（括号里是这次要透支的行动力，
    本回合累计不能超过 `MOVE_POINTS`）；
    旁边还有 `再想想（回去缠斗）`
  - `返回战场` —— 打完收工，回到地图
- **空格 或 回车**：等同于点第一个按钮（交手 / 继续缠斗 / 返回战场），不会误触"撤退"。
  **点将和挑落脚点那两屏例外**：那里的按钮都是"替自己做决定"，
  按空格什么都不做，必须用鼠标点
- **滚轮、↑ ↓、PageUp / PageDown**：翻看战斗过程（回合数多了以后可以往回翻）

交战界面左右两张卡片是攻守双方（姓名、武力智力、体力条、本回合的掉血范围、该谁做决定），
卡片右上角标着攻方从哪一格打过来（如"从 樊城（通路） 进攻"）、守方驻守在哪一格（如"驻守 襄阳（城池）"），
标题下也写着交战地点（守军两名时还会标出"第 N 场 / 共 N 场"），中间显示回合数，
下方"战斗过程"逐条列出每一回合双方各掉了多少、还剩多少体力——**两场的回合分开记**，
换人之后也会把上一场的守将名字正确留在历史里。守方卡片上还会写"阵中还有：某某"，提示后面等着谁。

界面右侧面板显示回合数与当前行动方；右边一行并排两块**常驻**的小面板：
左边是选中武将的详情（武力 / 智力 / 体力 / 移动力 / **所在地** / 脚下粮草，所在地写的是地名，
如"位于 襄阳（城池）"），右边是**比分板**（双方的总分 / 将领分 / 地盘分，算法见"胜负"，
标题右边还会报一句「争夺中 N 格」）。下面是战报和双方武将总览（**一栏一方并排**，阵亡的会标注；
两边上阵人数可以不一样多）。
总览一屏最多显示 `ROSTER_MAX_ROWS`（7）行，**上阵人数更多时变成可滚动的窗口**：把鼠标放在总览上滚滚轮翻看，
右边有一根滚动条，标题旁边写着「武将 1-7/14 滚轮翻看」。这样人再多也不会把上面的战报挤掉——
**战报区恒定留 4 行**，不随人数变化。
棋盘上每格底部写着地名（通路青灰、城池金色），黄色高亮是能走到的格子，红色高亮是能发动进攻的敌人格子，
鼠标悬停在任意格子上会弹出该格的「地名（地形）」——武将站在格子上时地名被压住，这样就能看。
同一格站两名武将时棋盘上左右分栏各画一半。

## 六、电脑对手

一人游玩时，另一边由电脑操控。它**只用手头这个局面**做判断，不偷看未来，也不需要预演整局；
每走一步都在主循环里暂停 `AI_STEP_FRAMES` 帧，所以你能看清它把谁挪到哪、什么时候冲锋——
侧边栏在它思考时会写"电脑思考中…"，它的每一步也都进战报。

### 它怎么算账：一切换算成"分数"

电脑的通用货币就是**比分板上那一套分**（将领分 = `(100+体力)×武力`；地盘分 = 每格地形分 + 格上粮草）。
拿它当评估函数有两个好处：一是"这一手赚不赚"和玩家看到的比分永远一致，不用再靠一堆拍出来的常数；
二是它天生就包含"打死对方一名武将 = 对方掉一大块"——一个满血武力 21 的武将值 4200 分，
**比一座城池还贵**，所以歼灭不需要另外写死，它自己就是最赚的一手。

不过账面分数看不见两件更要紧的事，所以电脑另外补上：

- **死人不会再回来**：歼灭的价值在账面之上再放大 `AI_KILL_WORTH` 倍。账面上杀掉他只是他掉一次分；
  实际上他还少了一个能一直赚分、能守土的子。
- **阵亡是断崖**：掉体力是线性掉分，掉光却是整名武将消失，所以"站在刀口下的风险"按身价折算，
  而不是只看这回合会掉多少体力。

### 它怎么推演一仗

每回合掉多少体力是 `[1, 2 × 对方武力]` 里的均匀随机数，所以平均值就是 `0.5 + 对方武力`。
两边同时掉血，所以**谁先倒下**就看"我打光他要几回合"和"他打光我要几回合"哪个小。
在这之上，它按**理性守将**的应对来估代价，这是这一版比上一版敢打的关键：

- 守将**赢不下这场**、又跑得掉 —— 他会撤（活命 > 守格）。所以除第一个守将必须挨的那一回合，
  攻方不再付代价；**打平也算"赢不下"**（守方打平就是同归于尽，理性守将宁可撤走）。
- 守将**退无可退**（被堵住、或这回合撤退额度用完）—— 只能死战：他输就是被**歼灭**，
  打平就是同归于尽。**这是本作唯一的歼灭入口**，所以电脑会数对方还剩几个落脚点，
  也会主动去堵那几格（`AI_SIEGE_WORTH`）。

推演里守方会真的**挪窝**：逼退一格，后面一串格子的归属就跟着变——地盘是按"谁的行动距离更近"
算的，所以"把守将赶走"就是推进的实质。

### 它在棋盘上做什么（`ai_map_step`）

一步里只有三个选项，全都换算成分数，所以**直接比大小**——"吃一口救命的粮"排在
"打一场无关痛痒的仗"前面是理所当然的，不需要额外的优先级规则：

1. **打一仗**：算最赚的那一仗（含歼灭加成、占地收益、战后会不会被反吃）。
   只赚不亏才动手；没便宜仗可打就去走位。
2. **吃一口粮**：回的那点体力直接就是将领分，代价是这堆粮本来算在自己地盘分里（每石 150）
   ——只有在**自己地盘上**吃才算代价。另外算一笔"救命分"：这一口能把"守不住"变成
   "守得住"，那就不是算小账的时候。
3. **走位**：按这套打分挑落脚点——回血快的地形、城池和粮草的分、**下一步能打谁**
   （同一回合内敌人插不进手，所以"走过去再冲"几乎能兑现）、**能不能堵住谁的退路**、
   以及**会不会被对方下回合吃掉**。全军还会盯着同一个目标压过去（各自找最近的敌人
   会把兵力摊开，两格堆两个人互相瞪眼就冻住了）。
   走的时候可能顺路搬粮，但只在两种情况下搬：**自己带着伤**（落到地方正好就地吃）
   或**要进城**（入库囤起来）。其余情况把粮留在原地——搬运的净效果是把粮挪到落点，
   见粮就搬的话会把城池的存粮一路拖散在野地里。一次最多搬 `AI_GRAIN_CARRY` 石。
4. 谁都没正经事做就**收工**，把回合交给对方。

每一步都真的花掉移动力或者结束回合，所以一个回合内必然收敛，不会卡在那里。
电脑**不走**"弹窗问带多少"那条路（那是给人类玩家的），它搬多少是直接算好的。

### 它在交战屏上做什么（`ai_battle_step`）

- **继续还是撤退**：和上面的推演共用同一套判断（守方那一支叫 `defender_stands_firm`），
  攻守两边不会算出两套账。攻方只要不输就压上去；守方赢不下就撤——但如果死战能把攻方
  磨薄到后面那位守将能接手，这一位就该顶住（拿便宜的换贵重的）。没退路时没得选，只能死战。
- **谁先出阵**（它是守方时）：两种出场顺序各推演一遍，挑我方损失最小的。
  谁单挑就拼得过攻方就派谁先上（他顶住，攻方就得撤，这一格白赚）。
- **往哪撤**（它是守方时）：先看安全（别撤到敌人嘴边，尤其别贴着武力高的），
  再看是不是城池（多回血、多拿分），最后才比代价（退得越远，下回合越迈不开腿）。

### 你和它在同一场交战里

决定权跟着阵营走，不跟着"谁在进攻"走：电脑进攻你驻守的那一格时，
**谁先出阵、继续还是撤退、往哪撤都还是你点**；轮到它做决定时，交战屏会等它（约 0.4 秒一步）。
它自己打完的交战会自动回到战场，你参与的那些仍然由你点"返回战场"。

### 想调它的性子

常量区那几个 `AI_*` 就是旋钮（含义见上面的常量速查表和 `ai.py` 的模块注释）：
`AI_STEP_FRAMES` 控制它出手快慢；`AI_KILL_WORTH` 调大它就更执着于歼灭；
`AI_THREAT_WORTH` 调大它就更惜命、更不肯孤军深入；`AI_SIEGE_WORTH` 调大它就更爱包抄围歼。

### 它现在还不擅长什么

它**只看一步**：把每种走法摆出来、按计分板算一遍分，挑最高的，然后重新评估下一步
（一步之内连着打几仗是靠"每步都重算"串起来的，所以连着打是会的）。
但跨回合的长期计划不行——比如"这个城池里堆着两名守将，我先磨他三个回合再总攻"
这种仗它看不到，所以碰上**死守不出的对手**，它多半是把对方围在城里、靠地盘分赢下来，
而不是硬啃。
